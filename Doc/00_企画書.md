## 1. 背景

日常の小さな用途に対して、必要な機能だけを持つ個人用ツールを継続的に追加できる場所を用意する。

## 2. 目的

複数の小さな機能を一つのAndroidアプリへまとめ、共通の操作感と開発基盤を使いながら、機能ごとの独立性を保って開発する。

## 3. 基本方針

- 配布するAndroidアプリは一つとする
- ホーム機能から各機能へ移動する
- 機能固有の実装と設計書は機能単位で分離する
- 端末内で完結できる処理はローカルで完結させる
- 必要になった機能だけFirebaseのデータサービスを利用する
- 思いついた機能を追加できる余地を残し、未決の機能名や仕様を先に固定しない

## 4. 初期スコープ

| 区分 | 内容 |
| --- | --- |
| `core` | 共通UI、保存、通知、Firebase接続境界などの共通基盤 |
| `home` | アプリの入口、機能一覧、共通設定への導線 |
| `pomodoro` | 最初に開発する機能。詳細仕様は機能別設計書で定義する |

## 5. 将来拡張

初期スコープに含めない機能は、名前・用途・画面・データ構造を現時点では定義しない。

将来追加する場合は、`feature/<機能名>` と `Doc/apps/<機能名>` を追加し、全体設計・共通基盤との境界を確認してから着手する。

## 6. 対象外

- 初期段階での複数APK化
- 未決の機能の先行実装
- 必要性が決まっていないFirebaseサービスの導入
- 個人利用に不要なアカウント・同期・分析機能の先行追加

## 7. 完了条件

- 一つのAndroidアプリとしてビルド・配布できる
- `home`から`pomodoro`へ移動できる
- 機能固有のコードと共通基盤の責務が分かれている
- CIでテスト、Lint、Debug APKビルドを実行できる
- Firebase App Distributionでテスト用APKを配布できる
