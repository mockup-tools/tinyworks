## 1. システム概要

tinyworksは、ホーム機能から複数の小さな機能へ移動できる一つのAndroidアプリとして構成する。

ホーム機能と各機能はアプリ内部で分離するが、配布物は一つのAPKとする。

## 2. リポジトリ構成

```text
tinyworks/
├─ README.md
├─ Doc/
│  ├─ 全体・共通設計書
│  └─ apps/
│     ├─ home/
│     └─ pomodoro/
├─ pgm/
│  └─ tinyworks/
│     └─ app/
│        └─ src/main/kotlin/io/github/mockuptools/tinyworks/
│           ├─ core/
│           └─ feature/
└─ .github/workflows/
```

`pgm`はコードとビルド設定を管理する場所とし、設計書は`Doc`で管理する。

## 3. Androidプロジェクト構成

```text
pgm/tinyworks/
└─ app/                    # 唯一のGradleアプリモジュール
   └─ src/main/kotlin/io/github/mockuptools/tinyworks/
      ├─ MainActivity.kt   # アプリ起動と全体ナビゲーション
      ├─ core/             # 機能間で共有する基盤
      │  └─ ...
      └─ feature/
         ├─ home/          # ホーム機能
         └─ pomodoro/      # Pomodoro機能
```

初期段階ではGradleモジュールを増やさず、パッケージ単位で分離する。将来の機能は、仕様が決まった時点で`feature/`へ追加する。未決の機能用ディレクトリは先に作成しない。

## 4. 依存関係のルール

```text
app
├─ feature/home
└─ feature/pomodoro
      ↓
     core
```

- `app`の起動処理と全体ナビゲーションは機能固有の処理を持たない
- `feature`は自分の画面・状態・データ処理を管理する
- `feature`同士は原則として直接依存しない
- `core`は`feature`へ依存しない
- 共通化は実際に複数機能で必要になったものに限定する

機能が大きくなった場合は、現在のパッケージ境界を維持したままGradleモジュールへ切り出す。

## 5. 画面構成

- 起動後は`home`を表示する
- `home`から利用可能な機能へ移動する
- 各機能からホームへ戻れる
- 機能固有の画面遷移は各機能内で完結させる

## 6. データ・通信方針

- 端末内で完結できる機能はローカル保存を基本とする
- `pomodoro`は初期段階でローカル処理を基本とする
- Firebaseのデータサービスは、同期・共有など明確な要件が生じた機能だけで利用する
- Firebaseの利用範囲は機能別設計書とプライバシー方針へ反映する

## 7. 配布方針

- Androidアプリは一つのFirebase Android Appとして登録する
- テスト配布はFirebase App Distributionを利用する
- CIはリポジトリ内の一つのAndroidプロジェクトを検証する
- 初期段階ではGoogle Playへの自動公開を行わない

## 8. 技術方針

- Kotlin
- Jetpack Compose
- Gradle Kotlin DSL
- namespace / release `applicationId`: `io.github.mockuptools.tinyworks`（暫定）
- debug配布用`applicationId`: `io.github.mockuptools.tinyworks.debug`
- 必要に応じたRoom、DataStore、WorkManagerなどのAndroid標準・Jetpack系ライブラリ
- 依存バージョンは固定して管理する
