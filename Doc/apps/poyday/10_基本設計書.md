## 1. 構成

実装場所は`pgm/tinyworks/app/src/main/kotlin/io/github/mockuptools/tinyworks/feature/poyday`とする。

機能内の責務は次のように分ける。

```text
feature/poyday
├─ PoyDayScreen              # メイン画面とタブ表示
├─ PoyDaySettingsScreen      # ゴミ出し設定画面
├─ PoyDayScheduleCalculator  # 設定から日付を算出するロジック
├─ PoyDayRepository          # SQLiteとの読み書き
├─ PoyDayDatabaseModule      # PoyDay固有のSQLiteスキーマ
└─ PoyDayWidgetProvider      # Androidウィジェット
```

画面は`PoyDayRepository`を直接呼び出さず、画面状態を組み立てる機能内の状態管理を経由して設定と算出結果を受け取る。`PoyDayScheduleCalculator`はAndroid UIやSQLiteに依存しない。

## 2. 共通基盤との境界

- 共通UIは`core/ui`の`TinyworksAppShell`を利用する
- SQLiteの接続と登録は`core/storage`の`TinyworksDatabase`を利用する
- `PoyDayDatabaseModule`、テーブル定義、`PoyDayRepository`は`feature/poyday`に置く
- ウィジェットからメイン画面を開く全体遷移は`MainActivity`が受け取る
- `feature/poyday`は`home`や`pomodoro`へ直接依存しない

## 3. 画面

### 3.1 メイン画面

ポイの日画面は「カレンダー」「設定」の2タブで構成する。画面外枠、ヘッダー、メニュー、上下の安全余白は共通アプリシェルを利用する。

カレンダータブには、現在月と翌月の2か月を表示する。

- 日曜日から土曜日の曜日見出しを表示する
- 日付セルには日付だけを基本表示する
- 該当するゴミ出し区分のアイコンを日付セル内へ表示する
- 同じ日に複数区分がある場合は、複数アイコンを表示する
- アイコンだけで区分を確認できるよう、画面下部に区分とアイコンの凡例を置く
- 月移動、予定の詳細表示、メモ入力は初期スコープに含めない

初期表示範囲は「今日を含む月」と「その翌月」とする。日付算出は端末のローカルタイムゾーンで行う。

### 3.2 設定タブ

可燃ゴミ・不燃ゴミ・資源ゴミの3区分を、それぞれ独立した設定カードとして表示する。各カードには区分固有のアイコンを表示する。

各カードの設定項目:

- 有効／無効
- 指定方法: `週` または `日`
- 指定方法が`週`の場合
  - 週パターン: `毎週`、`奇数週`、`偶数週`、`第1週`、`第2週`、`第3週`、`第4週`
  - 曜日: 日曜日～土曜日
- 指定方法が`日`の場合
  - 日: 1～31
- 保存

指定方法が`週`の場合は週パターンと曜日を必須とする。指定方法が`日`の場合は日を必須とする。無効にした区分はカレンダーとウィジェットへ表示しない。

## 4. 日付算出

`PoyDayScheduleCalculator`は、対象期間と3区分の設定を受け取り、日付ごとのゴミ出し区分一覧を返す。

### 4.1 週指定

週指定は設定された曜日に対して次の判定を行う。

| パターン | 判定 |
| --- | --- |
| 毎週 | 対象曜日なら該当 |
| 奇数週 | 対象曜日かつ週番号が奇数なら該当 |
| 偶数週 | 対象曜日かつ週番号が偶数なら該当 |
| 第1～4週 | 月内でその曜日が何回目に現れるかが指定値なら該当 |

第1～4週は、月の中で指定曜日が出現する順序を週番号として扱う。たとえば第2月曜日は、その月の月曜日の2回目の日付とする。該当する曜日が月に存在しない場合は予定なしとする。

奇数週・偶数週の週番号基準は未決事項であり、実装前に確定する。暫定実装ではISO 8601の週番号を使用する。

### 4.2 日指定

日指定は、毎月の指定日を該当日とする。

- 1～31を指定できる
- 対象月に指定日が存在しない場合は予定なしとする
- 例: 20を指定した場合、毎月20日を該当日とする

### 4.3 算出結果

算出結果は保存せず、次の画面表示に利用する値として扱う。

```text
PoyDayOccurrence(
    date,
    categories: [COMBUSTIBLE, NON_COMBUSTIBLE, RECYCLABLE]
)
```

同一日に複数区分が該当する場合は、区分をまとめて返す。画面とウィジェットは同じ算出ロジックを利用する。

## 5. データ

### 5.1 SQLiteの責務

SQLiteにはゴミ出し設定だけを保存する。カレンダーの日付、ウィジェット用の表示データ、算出済みの予定は保存しない。

画面表示側とSQLite側の境界は次のとおりとする。

```text
設定画面
  ↓ 設定モデル
PoyDayRepository
  ↓
SQLite: poyday_rules

SQLite: poyday_rules
  ↓ 読み込み
PoyDayScheduleCalculator
  ↓ 算出結果
カレンダー / ウィジェット
```

### 5.2 設定モデル

```text
PoyDayRule
  category: COMBUSTIBLE | NON_COMBUSTIBLE | RECYCLABLE
  enabled: Boolean
  mode: WEEK | DAY_OF_MONTH
  weekPattern: EVERY | ODD | EVEN | FIRST | SECOND | THIRD | FOURTH
  weekday: SUNDAY ... SATURDAY
  dayOfMonth: 1 ... 31
```

`mode`に応じて不要な項目は`null`とする。3区分につき1件の設定を持つ。初回起動時は3区分を無効状態で作成する。

### 5.3 SQLiteテーブル

テーブル名は`poyday_rules`とする。

| カラム | 型 | 内容 |
| --- | --- | --- |
| `category` | TEXT PRIMARY KEY | 区分識別子 |
| `enabled` | INTEGER NOT NULL | 0:無効、1:有効 |
| `mode` | TEXT NOT NULL | `WEEK` または `DAY_OF_MONTH` |
| `week_pattern` | TEXT | 週パターン |
| `weekday` | INTEGER | 曜日。日曜を0として扱う |
| `day_of_month` | INTEGER | 毎月の日。1～31 |
| `updated_at_epoch_millis` | INTEGER NOT NULL | 更新時刻 |

`PoyDayDatabaseModule`が`CREATE TABLE IF NOT EXISTS`と初期3区分の登録を行う。スキーマ変更時は`core/storage`のSQLite基盤から機能モジュールのマイグレーションを呼び出す。

## 6. ウィジェット

Android AppWidgetとして実装し、対象サイズは横5マス・縦2マスの1パターンだけとする。

- 日曜日～土曜日の7列を表示する
- 上段に今週、下段に翌週を表示する
- 各セルへ日付と該当区分のアイコンを表示する
- アイコンがない日は日付だけを表示する
- 同一日に複数区分がある場合は複数アイコンを表示する
- ウィジェットのタップで`MainActivity`を開き、ポイの日のカレンダータブを表示する
- 設定保存後とウィジェット更新時に、設定を読み込み直して表示を更新する

ウィジェットは独自の日付算出を持たず、`PoyDayScheduleCalculator`の結果を利用する。ウィジェット固有の表示処理は`PoyDayWidgetProvider`に閉じ込める。

## 7. テスト

### 単体テスト

- 毎週の指定曜日が算出される
- 奇数週・偶数週が算出される
- 第1～4週の指定曜日が算出される
- 毎月1～31日の指定日が算出される
- 2月などに存在しない日が算出されない
- 無効な区分が算出結果へ含まれない
- 同一日に複数区分を返せる
- 月をまたぐ対象期間を正しく算出できる
- 設定の保存と読み込みができる

### 画面確認

- ホームまたはメニューからポイの日へ遷移できる
- 2か月分のカレンダーが表示される
- 設定した区分のアイコンがカレンダーへ表示される
- 設定タブで週指定と日指定を切り替えられる
- 可燃ゴミ・不燃ゴミ・資源ゴミを個別に保存できる
- 保存後にカレンダーとウィジェットへ反映される
- ウィジェットに今週・翌週の日曜日～土曜日が表示される
- ウィジェットのタップでポイの日メイン画面が開く
