## 1. 初期運用

- 個人利用を前提とする
- Firebase App DistributionでテストAPKを配布する
- 実機での確認結果を記録してから継続利用する
- Google Play公開は初期スコープに含めない

## 2. 更新の流れ

```text
設計・実装
  ↓
Pull Request / push
  ↓
CI
  ↓
mainへの反映
  ↓
Firebase App Distribution
  ↓
実機確認
```

## 3. 機能追加

新しい機能を追加する場合は、先に機能名・目的・データの扱い・通信の有無を定義する。その後、`feature`と`Doc/apps`へ追加する。

未決の機能を仮の名前で先行登録しない。
