# スクーター管理 基本設計書

## 構成と責務

`feature/scooter`内にデータモデル・計算、Repository、写真処理、画面、登録フォームを置く。他機能への依存を持たず、`MainActivity`がホーム／ドロワーの遷移を組み立てる。既存の`TinyworksAppShell`とSQLite登録契約を使用する。

## データ

| テーブル | キー・内容 |
| --- | --- |
| scooter_vehicles | id、自車情報JSON（車種、ナンバー、区分、有効、購入日・金額、レンタル会社・開始終了日・月額、メモ、写真ファイル名） |
| scooter_rides | id、vehicle_id、業務走行JSON（乗降日時・ODO・メモ） |
| scooter_annual | vehicle_idとyearの複合主キー、基準ODO JSON（年度、開始・終了日、開始・終了ODO） |
| scooter_expenses | id、vehicle_id、給油／整備JSON（日付・ODO・金額・給油量・内容） |

JSONペイロードは`version: 1`を持つ。日時は端末ローカル日時のISO表記。ODOは整数km、金額は整数円、給油量はLの小数とする。車両別の索引を設ける。新規テーブルは登録済みモジュールの`CREATE TABLE IF NOT EXISTS`で追加し、既存DBバージョンと他機能のテーブルを変更しない。既存ペイロードを変更する将来の変更では移行処理を定義する。

読み書きと画像の変換はIOディスパッチャーで行い、失敗時は再試行できる表示を出す。複数行にまたがる車両削除と、前後の記録を検証する業務走行保存はトランザクションで実行する。

## 按分

車両・年度ごとに計算する。

- 業務距離 = 完了した各走行の（降車ODO − 乗車ODO）の合計
- 総距離 = 最終ODO − 年始／利用開始時ODO
- 業務利用割合 = 業務距離 ÷ 総距離 × 100
- 私用距離 = 総距離 − 業務距離、私用割合 = 100 − 業務利用割合

年途中の車両利用開始は、その日のODOを基準にする。年途中の集計は最終ODOに集計時点の値を入れる。月別グラフはその年の完了した記録を乗車月で集計する。費用は選択年の給油・整備の登録金額の合計（按分前）。

基準値未登録、総距離ゼロ、基準値逆転、乗車中の記録、走行日時の重複、ODO逆転、業務距離の超過、基準日の期間外の走行、基準ODO範囲外の走行がある場合は割合を表示せず案内する。年度内の走行を黙って除外しない。未来の走行や費用は登録できない。年をまたぐ走行は、年末・年始で記録を分ける。ODOは車両ごとに独立し、複数車両を同時に乗車中にする制約は設けない。

## 車両情報と写真

購入／レンタルの選択に応じて入力項目を切り替える。非表示の区分の値も保持する。有効／無効は履歴の表示・計算・編集を制限しない。有効な車両、無効な車両の順に、各グループ内は登録順で並べる。

Android Photo Pickerを使い、写真一覧への広範な権限は要求しない。選択画像を最大1280pxに縮小してJPEGに変換し、メタデータを除き、`filesDir/scooter_photos/<UUID>.jpg`に保存する。SQLiteにはファイル名のみ保存。元画像を消してもアプリ内の画像は残る。表示用は最大400pxに縮小する。写真の変更・削除時は保存成功後に旧画像を削除する。未保存の選択画像はキャンセル時に削除する。

## 削除とプライバシー

各記録の編集画面から確認後に削除できる。車両の全削除はその車両の走行・基準ODO・費用・写真を削除する。履歴を保持したい場合は無効化を使う。アプリデータの削除でも消去できる。既存の`allowBackup=false`を維持する。

## 検証

単体テストで80%・0%・100%の割合、年途中利用、基準値不足、乗車中、期間外、年度境界、重複、前後ODO逆転、車両の独立性、自己編集を確認する。リポジトリ共通の単体テスト・Lint・Debug APKビルドを実行する。

実機確認項目：初回の空状態、複数車両、4タブのタップ／スワイプ、購入・レンタルの値の保持、写真の選択／元画像削除／変更／削除、乗車→終了→再起動→降車、年度変更、記録編集／削除、無効化の並び順、ダークテーマ、文字拡大、回転、キーボードとシートのスクロール。
