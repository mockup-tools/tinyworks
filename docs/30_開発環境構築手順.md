## 1. 開発環境の方針

ローカル環境へAndroid開発環境を個別に構築することを必須にせず、GitHub Codespacesを正とする。リポジトリ直下の`.devcontainer`で開発環境を固定する。

## 2. 固定するもの

- JDK 17
- Android SDK Command-line Tools
- Android SDK API 37
- Android SDK Build Tools 37.0.0
- Gradle Wrapper
- Kotlin・Android Gradle Plugin・Composeなどの依存バージョン

Gradle Wrapperと依存バージョンはAndroidプロジェクトへ固定して含める。

## 3. Codespacesの作成

1. GitHubでリポジトリを開く。
2. **Code → Codespaces → Create codespace on main**を選ぶ。
3. `.devcontainer`からコンテナを作成する。
4. ターミナルでJDK、Android SDK、Gradle Wrapperを確認する。

```text
java -version
sdkmanager --version
cd android
./gradlew --version
```

## 4. プロジェクトルート

Gradleプロジェクトのルートは次の場所とする。

```text
android
```

Android Studioで開く場合も、このディレクトリを選ぶ。リポジトリ直下にはGradleプロジェクトを置かない。

ローカルで開発する場合はJDK 17、Android SDK API 37、Build Tools 37.0.0を用意し、`JAVA_HOME`と`ANDROID_HOME`を設定する。SDKの場所は`android/local.properties`の`sdk.dir`でも指定できる。`local.properties`はコミットしない。

## 5. 初期確認

`android/`で次の確認を行う。CIでも同じタスクを実行する。

```text
./gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug
```

Windows（PowerShell）では次を実行する。

```powershell
.\gradlew.bat --no-daemon testDebugUnitTest lintDebug assembleDebug
```

生成されるDebug APKは`android/app/build/outputs/apk/debug/app-debug.apk`にある（リポジトリ直下からのパス）。実機・エミュレーターはAPI 37以上を使用する。

## 6. CIとの関係

GitHub Actionsでは、Codespacesと同じくJDK 17、Android SDK API 37、Build Tools 37.0.0を使用する。`android/`で単体テスト、Android Lint、Debug APKビルドを実行する。プロジェクトが存在しない場合もスキップせず失敗として扱う。
