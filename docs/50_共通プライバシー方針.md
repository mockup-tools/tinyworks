## 1. 基本方針

個人用アプリとして、必要最小限のデータだけを扱う。機能の実装前に、保存場所、通信の有無、削除方法を定義する。

## 2. 初期方針

- 端末内で完結できる機能は端末内で処理する
- 不要なログイン、広告、アクセス解析を先行導入しない
- Firebaseを利用する場合は、利用機能ごとに目的とデータ範囲を明記する
- Firebase App Distributionで扱われる配布情報と、アプリ内データを区別する

## 3. Pomodoroの保存内容

- 作業時間・休憩時間の設定と作業セッション履歴を端末内SQLiteへ保存する
- 保存データはPomodoro機能の設定表示と履歴・統計集計にだけ利用する
- アプリ外への送信、Firebaseへの同期、アカウントとの紐付けは行わない
- Pomodoroの統計・履歴タブから保存データを全削除できる
- Androidのアプリデータ削除でも端末内データを削除できる

## スクーター管理の保存内容

- 車種・ナンバー、購入／レンタル情報、ODOと業務走行日時、給油・整備・費用・メモを端末内SQLiteへ保存する。
- 利用者が選択した車両写真は縮小・メタデータ除去したコピーをアプリ専用領域へ保存する。元写真には変更を加えない。
- データと写真は車両管理・走行距離の集計・業務利用割合の計算にだけ利用し、外部送信・クラウド同期・Uberやアカウントとの連携は行わない。
- 保存期間は利用者が削除するまで。記録・写真は編集画面から削除でき、車両削除時は関連する記録と写真をすべて削除する。無効化ではデータを消去しない。
- Androidのアプリデータ削除でも消去できる。アプリのバックアップ無効設定を維持する。

## 4. 機能追加時の確認

- 取得する情報
- 保存場所
- 保存期間
- 外部送信の有無
- 利用者による削除方法
- Firebase Security Rulesの範囲
